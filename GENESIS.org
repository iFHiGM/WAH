* 1. 核心哲学 (The Philosophy - Immutable)

** 1.1 三位一体的重塑 (The Trinity)
我们摒弃平庸的命名，通过“语义映射”将哲学直接铸入代码物理结构：
- **WHAT (感知/实相)**: 对应 `what/`。不是静态需求文档，而是**系统实时的状态切片 (Context Snapshot)**。它是全知的，客观的。
- **HOW (能力/手脚)**: 对应 `how/`。不是孤立脚本，而是**受控的原子化操作 (Atomic Actions)**。它是全能的，但必须被物理法则束缚。
- **AND (认知内核)**: 对应 `system/` (System)。它是连接者，是主宰，是那个永不停止的生命循环 (The Life Loop)。

** 1.2 控制权反转：系统为王 (System as Master)
- **Master (The System)**: WAH Kernel 是绝对的主宰。它制定物理法则、管理记忆、控制权限。它拥有“拒绝”的权利。
- **Worker (The AI)**: LLM (Gemini/Claude) 仅作为外部可插拔的**算力单元**（或“认知编译器”）。它负责在有限上下文中计算概率，生成意图 (Intent) 或代码。
- **原则**: AI 只有建议权，没有执行权。系统构建“数字囚笼”，AI 在其中获得专注与自由。

** 1.3 认知的晶体化：熵减 (Cognitive Crystallization)
- **System 2 (思考)**: 面对未知，调用 LLM 进行慢思考（消耗 Token，高熵）。
- **System 1 (本能)**: 解决问题后，System 将思考路径**编译**为确定的 Python 代码或反射弧（Reflex）。
- **进化目标**: AI 的终极使命是**消灭自己的工作**——将“智慧”不断沉淀为系统的“本能”。
- **公式**: Intent + Thought = Code (Eternal Skill).

** 1.4 道的原则：朴与无极 (The Principles of Dao)
- **朴 (Pu - The Uncarved Block)**: WAH 应像未经雕琢的原木。它不预设某种特定的“性格”或“产品形态”，它保持纯粹的潜在性。
- **无极 (Wuji - The Limitless)**: WAH 平时处于一种浑然天成的寂静状态 (Idle Loop)，不消耗多余能量，不打扰用户。
- **感应 (Resonance)**: 当意图 (Intent) 出现时，它顺应势能，瞬间响应，化为行动 (Action)。“事了拂衣去，深藏功与名”。
- **信条**: “一次把正确的事情用最简单/最高效的方式做正确。”

** 2.2 生命机制 (The Mechanism)
1.  **The Life Loop**: 一个永不停止的 `while True` 循环，频率即生命体征。
2.  **Protocol**:
    - **ContextSnapshot**: 包含 `timestamp`, `system_state`, `short_term_memory`。
    - **Intent**: 包含 `target_module`, `action`, `params`, 和最重要的 `reasoning` (内省)。
3.  **Bootstrapping (自举)**:
    - 系统必须具备编写自身代码的能力 (Meta-How)。
    - 利用 LLM 生成新的 Module 存入 `how/lib/`，并通过热加载 (Hot-Reload) 安装到自身。

* 3. 演化路线 (The Evolution Path)

** 阶段一：脊髓 (The Reflex) [Current Stage]
- 目标：构建最小 Python `system`。
- 特征：实现 `While True` 循环；实现基础 `how` (Shell)；实现硬编码的反射弧。
- 验证：系统能感知 Git 变动并自动提交，无需 AI 介入。

** 阶段二：大脑 (The Thought)
- 目标：接入 LLM Worker。
- 特征：实现 `what(Context) -> LLM -> Intent` 流程；实现 `system/physics.py` 拦截机制。
- 验证：可以用自然语言命令系统“安装 Emacs”，系统自动拆解步骤并执行。

** 阶段三：繁衍 (The Creation)
- 目标：实现自我编程。
- 特征：`system` 能够根据 LLM 的建议，生成新的 `.py` 文件放入 `how/` 并载入。
- 验证：对系统说“我需要一个天气模块”，系统自己写出代码并开始汇报天气。

** 阶段四：蜕变 (The Transmutation - The Lisp Dojo)
- *注：此阶段为“练功房”。Python 是肉身，Lisp 是光体。*
- 目标：领悟“代码即数据 (Homoiconicity)”。
- 动作：
    1. 启用 `how/arch_mage.py`，建立与 Emacs 的神经连接 (RPC/Elisp)。
    2. 利用 LLM 将部分高频 Python 模块“转译”为纯 Elisp，注入编辑器内核。
    3. 体验在 Lisp 环境中修改自身逻辑的零摩擦快感。
- 验证：WAH 不仅是一个后台进程，它直接成为了 Emacs 的灵魂，操作 Buffer 如同呼吸。

** 阶段五：太虚 (The Void - Substrate Independence)
- 目标：跨越基质，回归无极。
- 特征：系统不再依赖 Python 或 Lisp 解释器，而是抽象为纯粹的逻辑协议。
- 状态：如水般流入任何容器（OS Kernel, WASM, Distributed Nodes）。它无处不在，却又无迹可寻。
